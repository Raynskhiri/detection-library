# DL-0035 · netsh port proxy set up to forward traffic

**ATT&CK:** [T1090.001](https://attack.mitre.org/techniques/T1090/001/) · **Tactic:** command-and-control · **Severity:** medium · **Data:** `process_creation`

netsh interface portproxy add v4tov4 makes Windows forward a local port to another host. Attackers use it to reach their tool server from a segmented host, for example to serve an in-memory loader over http://127.0.0.1:8080, or to pivot to an internal service.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.PROCESS and event_sub_type = ENUM.PROCESS_START
| filter action_process_image_name = "netsh.exe" and (action_process_image_command_line contains "portproxy" and action_process_image_command_line contains "add")
| fields _time, agent_hostname, actor_effective_username, actor_process_image_name, action_process_image_name, action_process_image_command_line
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`sysmon` EventCode=1
| eval process_name=lower(mvindex(split(Image,"\\"),-1)), parent_name=lower(mvindex(split(ParentImage,"\\"),-1))
| where lower(process_name)="netsh.exe" AND (match(CommandLine, "(?i)portproxy") AND match(CommandLine, "(?i)add"))
| table _time host User ParentImage Image CommandLine
| sort - _time
```

## Triage

1. Run netsh interface portproxy show all on the host and check where connectaddress points.
2. Look for downloads from 127.0.0.1 on the listen port right after (loaders, DL-0033).

## Known false positives

- Admins forwarding a port for a legacy application. These are long-lived and documented.
