# DL-0052 · Resource-based constrained delegation written on an object

**ATT&CK:** [T1098](https://attack.mitre.org/techniques/T1098/), [T1134.001](https://attack.mitre.org/techniques/T1134/001/) · **Tactic:** privilege-escalation · **Severity:** high · **Data:** `windows_event`

Event 5136 changing msDS-AllowedToActOnBehalfOfOtherIdentity. Whoever is listed there can impersonate any user to that computer. With write rights on a computer object (for example GenericWrite), an attacker adds a machine account they control and then uses S4U to become an administrator on it.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_attribute_name = json_extract_scalar(action_evtlog_data_fields, "$.AttributeLDAPDisplayName")
| filter action_evtlog_event_id = 5136 and evt_attribute_name = "msds-allowedtoactonbehalfofotheridentity"
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=5136 AND lower(AttributeLDAPDisplayName)="msds-allowedtoactonbehalfofotheridentity"
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Read the new security descriptor to see which account was granted, then clear the attribute.
2. Find who could write to the computer object (the ACL path) and remove that right.

## Known false positives

- Admins setting up RBCD for a real application. Rare and should be change-managed.
