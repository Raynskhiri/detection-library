# DL-0049 · TGT requested with RC4 encryption (possible overpass-the-hash)

**ATT&CK:** [T1550.002](https://attack.mitre.org/techniques/T1550/002/) · **Tactic:** lateral-movement · **Severity:** medium · **Data:** `windows_event`

Event 4768 with encryption 0x17. Modern Windows clients ask for AES. A TGT requested with RC4 is what you see when an NTLM hash is turned into a Kerberos ticket (Rubeus asktgt /rc4, mimikatz sekurlsa::pth).

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_ticket_encryption = json_extract_scalar(action_evtlog_data_fields, "$.TicketEncryptionType"), evt_preauth_type = json_extract_scalar(action_evtlog_data_fields, "$.PreAuthType")
| filter (action_evtlog_event_id = 4768 and evt_ticket_encryption = "0x17") and not ((evt_preauth_type != null and evt_preauth_type = "0"))
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where (EventCode=4768 AND lower(TicketEncryptionType)="0x17") AND NOT ((isnotnull(PreAuthType) AND lower(PreAuthType)="0"))
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Check where the hash came from. The source host in the event is the attacker's foothold.
2. Disable RC4 in the domain where possible, so this becomes a high-fidelity signal.

## Known false positives

- Accounts and devices that only support RC4. They are the same every day, so baseline them.
