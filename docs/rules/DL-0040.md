# DL-0040 · .NET profiler set to load a DLL (COR_PROFILER)

**ATT&CK:** [T1574.012](https://attack.mitre.org/techniques/T1574/012/), [T1562.001](https://attack.mitre.org/techniques/T1562/001/) · **Tactic:** defense-evasion · **Severity:** high · **Data:** `registry_set`

Setting COR_ENABLE_PROFILING and COR_PROFILER in the Environment key makes every .NET process, including PowerShell, load a DLL of the attacker's choice. Tools such as InviShell use it to switch off PowerShell logging and AMSI for the user.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.REGISTRY and event_sub_type = ENUM.REGISTRY_SET_VALUE
| filter action_registry_key_name ~= "(?i)\\\\Environment$" and action_registry_value_name in ("cor_profiler", "cor_enable_profiling", "cor_profiler_path")
| fields _time, agent_hostname, actor_process_image_name, action_registry_key_name, action_registry_value_name, action_registry_data
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`sysmon` EventCode=13
| eval process_name=lower(mvindex(split(Image,"\\"),-1)), reg_key=replace(TargetObject,"\\\\[^\\\\]*$",""), reg_value=mvindex(split(TargetObject,"\\"),-1)
| where match(reg_key, "(?i)\\\\Environment$") AND (lower(reg_value)="cor_profiler" OR lower(reg_value)="cor_enable_profiling" OR lower(reg_value)="cor_profiler_path")
| table _time host Image TargetObject Details
| sort - _time
```

## Triage

1. Read COR_PROFILER_PATH. A DLL in a user folder means a bypass, not an APM agent.
2. Expect missing PowerShell 4104 logs from that user after this point. Look at process creation instead.

## Known false positives

- Application performance monitoring agents (APM) that profile .NET apps. They set it machine-wide from their own installer.
