# DL-0077 · Secret or certificate added to an Entra ID app by another app or by a script

**ATT&CK:** [T1098.001](https://attack.mitre.org/techniques/T1098/001/) · **Tactic:** persistence · **Severity:** high · **Data:** `entra_audit`

A client secret or certificate was added to an application or service principal ("Add service principal credentials", or "Update application - Certificates and secrets management"), and the change came from an application rather than a person, or from a scripting client (python-requests, Python-urllib, curl). A credential on an app is a backdoor that survives password resets, MFA and the vendor fixing its own breach. In the October 2026 ConnectWise compromise, a Python script added new secrets to an MSP management app and to a security vendor's app minutes after taking Global Administrator.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = msft_azure_ad_audit_raw
| filter activityDisplayName != null
| alter aud_operation = activityDisplayName, aud_initiator_app = json_extract_scalar(initiatedBy, "$.app.displayName"), aud_initiator_user = json_extract_scalar(initiatedBy, "$.user.userPrincipalName"), aud_target_type = json_extract_scalar(targetResources, "$[0].type"), aud_target_name = json_extract_scalar(targetResources, "$[0].displayName"), aud_targets = to_string(targetResources), aud_user_agent = arrayindex(regextract(to_string(additionalDetails), "User-Agent\\\",\\\"value\\\":\\\"([^\\\"]*)"), 0)
| filter aud_operation ~= "(?i)^(add service principal credentials|update application.*certificates and secrets)" and (aud_initiator_app ~= "(?i).+" or aud_user_agent ~= "(?i)(python-requests|python-urllib|curl/|go-http-client|azure-toolkit)")
| fields _time, aud_operation, aud_initiator_app, aud_initiator_user, aud_target_type, aud_target_name, aud_user_agent, aud_targets
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`azure_monitor_aad` category=AuditLogs
| eval aud_operation=operationName, aud_category=category, aud_result='properties.result', aud_initiator_app='properties.initiatedBy.app.displayName', aud_initiator_app_id='properties.initiatedBy.app.appId', aud_initiator_user='properties.initiatedBy.user.userPrincipalName', aud_target_type=mvindex('properties.targetResources{}.type',0), aud_target_name=mvindex('properties.targetResources{}.displayName',0), aud_targets=mvjoin(mvappend('properties.targetResources{}.displayName','properties.targetResources{}.modifiedProperties{}.newValue')," | "), aud_user_agent=mvindex('properties.additionalDetails{}.value',mvfind('properties.additionalDetails{}.key',"User-Agent"))
| where match(aud_operation, "(?i)^(add service principal credentials|update application.*certificates and secrets)") AND (match(aud_initiator_app, "(?i).+") OR match(aud_user_agent, "(?i)(python-requests|python-urllib|curl/|go-http-client|azure-toolkit)"))
| table _time aud_operation aud_initiator_app aud_initiator_user aud_target_type aud_target_name aud_user_agent aud_targets
| sort - _time
```

## Triage

1. Open the target app's credentials and note the key ID, type, start and end dates. Attackers often pick long lifetimes; reporting on this campaign called out new secrets that expire in 2028.
2. Check whether the initiating app recently gained a directory role (DL-0076). Self-assigned role then new secrets is the full Storm-0940 chain.
3. Remove the credential, then review every sign-in by the target app since the credential was created. Removing it does not undo what was already read.

## Known false positives

- Secret rotation done by your own automation (Key Vault rotation, Terraform or a DevOps service principal). Allow-list that app by ID, not by name.
