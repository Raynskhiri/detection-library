# DL-0069 · New administrator account created on a FortiGate

**ATT&CK:** [T1136.001](https://attack.mitre.org/techniques/T1136/001/), [T1098](https://attack.mitre.org/techniques/T1098/) · **Tactic:** persistence · **Severity:** high · **Data:** `fortigate`

An object was added under system.admin. Attackers who get into a FortiGate create their own admin, often with a generic name (support, ssl-admin, backup, itadmin, secadmin, svcadmin), so they keep access after the bug is patched. Admin accounts are created a few times a year, so every hit deserves a look. FortiGate event log only.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = fortinet_fortigate_raw
| filter _raw_log != null
| alter fg_logid = arrayindex(regextract(_raw_log, "\\blogid=\"?([^\"\\s]*)"), 0), fg_action = arrayindex(regextract(_raw_log, "\\baction=\"?([^\"\\s]*)"), 0), fg_user = arrayindex(regextract(_raw_log, "\\buser=\"?([^\"\\s]*)"), 0), fg_srcip = arrayindex(regextract(_raw_log, "\\bsrcip=\"?([^\"\\s]*)"), 0), fg_ui = arrayindex(regextract(_raw_log, "\\bui=\"?([^\"\\s]*)"), 0), fg_cfgpath = arrayindex(regextract(_raw_log, "\\bcfgpath=\"?([^\"\\s]*)"), 0), fg_devname = arrayindex(regextract(_raw_log, "\\bdevname=\"?([^\"\\s]*)"), 0), fg_logdesc = arrayindex(regextract(_raw_log, "\\blogdesc=\"([^\"]*)\""), 0), fg_msg = arrayindex(regextract(_raw_log, "\\bmsg=\"([^\"]*)\""), 0)
| filter fg_cfgpath = "system.admin" and fg_action = "add"
| fields _time, fg_devname, fg_logid, fg_user, fg_srcip, fg_ui, fg_logdesc, fg_msg
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`fortigate`
| where lower(cfgpath)="system.admin" AND lower(action)="add"
| table _time devname logid user srcip ui logdesc msg
| sort - _time
```

## Triage

1. Read who created it (user), from where (ui shows the method and IP) and when. A creator that logged in through SSO or from the internet (DL-0068) is a compromise until proven otherwise.
2. Check the new account's profile and trusted hosts, and whether it also got VPN access.
3. Some implants delete their admin after use, so look for an Add and a Delete of the same cfgobj close together.

## Known false positives

- A planned change by your own team. Match it to a change ticket and to the admin who made it (user and ui fields).
