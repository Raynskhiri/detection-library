# DL-0054 · Key credential added to an account (shadow credentials)

**ATT&CK:** [T1098](https://attack.mitre.org/techniques/T1098/), [T1556](https://attack.mitre.org/techniques/T1556/) · **Tactic:** persistence · **Severity:** high · **Data:** `windows_event`

Event 5136 writing msDS-KeyCredentialLink. Windows Hello for Business writes this attribute on enrollment, but an attacker with write rights on an account can add their own key and then log on as that account with a certificate (PKINIT), without knowing or changing its password.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_attribute_name = json_extract_scalar(action_evtlog_data_fields, "$.AttributeLDAPDisplayName")
| filter action_evtlog_event_id = 5136 and evt_attribute_name = "msds-keycredentiallink"
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=5136 AND lower(AttributeLDAPDisplayName)="msds-keycredentiallink"
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. If the writer is not the device itself, list and remove unknown keys on the account (Whisker list / Get-ADUser -Properties msDS-KeyCredentialLink).
2. Expect a PKINIT logon for the same account soon after (DL-0050).

## Known false positives

- Windows Hello for Business enrollment. Those are written by the computer account of the device, for the user who enrolled.
