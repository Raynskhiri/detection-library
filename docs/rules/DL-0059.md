# DL-0059 · DSRM administrator password changed

**ATT&CK:** [T1098](https://attack.mitre.org/techniques/T1098/) · **Tactic:** persistence · **Severity:** high · **Data:** `windows_event`

Event 4794 on a domain controller: someone set the Directory Services Restore Mode administrator password. Combined with DsrmAdminLogonBehavior (DL-0041), that account becomes a quiet backdoor into the DC.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName")
| filter action_evtlog_event_id = 4794
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=4794
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Check the subject account and whether a change was planned. If not, reset the DSRM password and check DL-0041 on the same DC.

## Known false positives

- DC builds and planned DSRM password rotation.
