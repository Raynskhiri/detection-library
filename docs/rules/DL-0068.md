# DL-0068 · FortiGate admin login through FortiCloud SSO or from an internet address

**ATT&CK:** [T1190](https://attack.mitre.org/techniques/T1190/), [T1078](https://attack.mitre.org/techniques/T1078/) · **Tactic:** initial-access · **Severity:** high · **Data:** `fortigate`

A successful administrator login on a FortiGate that used FortiCloud SSO, or that came from an address outside RFC 1918. The 2026 FortiGate campaigns (CVE-2025-59718, CVE-2025-59719, CVE-2026-24858) all start this way: a crafted SAML login or an attacker's own FortiCloud account gives admin access in seconds, from the internet. Needs only the FortiGate event log, so it works for clients that send nothing else.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = fortinet_fortigate_raw
| filter _raw_log != null
| alter fg_logid = arrayindex(regextract(_raw_log, "\\blogid=\"?([^\"\\s]*)"), 0), fg_subtype = arrayindex(regextract(_raw_log, "\\bsubtype=\"?([^\"\\s]*)"), 0), fg_action = arrayindex(regextract(_raw_log, "\\baction=\"?([^\"\\s]*)"), 0), fg_status = arrayindex(regextract(_raw_log, "\\bstatus=\"?([^\"\\s]*)"), 0), fg_user = arrayindex(regextract(_raw_log, "\\buser=\"?([^\"\\s]*)"), 0), fg_srcip = arrayindex(regextract(_raw_log, "\\bsrcip=\"?([^\"\\s]*)"), 0), fg_ui = arrayindex(regextract(_raw_log, "\\bui=\"?([^\"\\s]*)"), 0), fg_method = arrayindex(regextract(_raw_log, "\\bmethod=\"?([^\"\\s]*)"), 0), fg_devname = arrayindex(regextract(_raw_log, "\\bdevname=\"?([^\"\\s]*)"), 0), fg_logdesc = arrayindex(regextract(_raw_log, "\\blogdesc=\"([^\"]*)\""), 0), fg_msg = arrayindex(regextract(_raw_log, "\\bmsg=\"([^\"]*)\""), 0)
| filter (fg_subtype = "system" and fg_action = "login" and fg_status = "success") and ((fg_method = "sso" or fg_ui ~= "(?i)^sso") or not ((fg_srcip != null and (incidr(fg_srcip, "10.0.0.0/8") or incidr(fg_srcip, "172.16.0.0/12") or incidr(fg_srcip, "192.168.0.0/16") or incidr(fg_srcip, "127.0.0.0/8")))))
| fields _time, fg_devname, fg_logid, fg_user, fg_srcip, fg_ui, fg_logdesc, fg_msg
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`fortigate`
| where (lower(subtype)="system" AND lower(action)="login" AND lower(status)="success") AND ((lower(method)="sso" OR match(ui, "(?i)^sso")) OR NOT ((isnotnull(srcip) AND (cidrmatch("10.0.0.0/8", srcip) OR cidrmatch("172.16.0.0/12", srcip) OR cidrmatch("192.168.0.0/16", srcip) OR cidrmatch("127.0.0.0/8", srcip)))))
| table _time devname logid user srcip ui logdesc msg
| sort - _time
```

## Triage

1. Check the source IP against the IOCs in the Fortinet advisories (FG-IR-26-060) and look at what the session did next. Config download (DL-0070), new admin (DL-0069) or a permissive policy (DL-0071) within minutes means compromise.
2. Confirm the firmware is patched and set admin-forticloud-sso-login to disable under config system global until it is.
3. Restrict the management interface to trusted hosts. An admin GUI reachable from the internet is the root problem.

## Known false positives

- Admins who really use FortiCloud SSO. List them and confirm each login with the person.
- Management from a provider or MSSP public IP. Allow-list those exact addresses, never a whole range.
