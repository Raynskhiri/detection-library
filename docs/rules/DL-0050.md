# DL-0050 · TGT requested with a certificate (PKINIT)

**ATT&CK:** [T1649](https://attack.mitre.org/techniques/T1649/), [T1550](https://attack.mitre.org/techniques/T1550/) · **Tactic:** credential-access · **Severity:** medium · **Data:** `windows_event`

Event 4768 with pre-authentication type 16 or 17 means the account logged on with a certificate. In a domain without smart cards this is rare, and it is how a certificate obtained through AD CS abuse or shadow credentials is turned into a login.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_preauth_type = json_extract_scalar(action_evtlog_data_fields, "$.PreAuthType")
| filter action_evtlog_event_id = 4768 and evt_preauth_type in ("15", "16", "17")
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=4768 AND (lower(PreAuthType)="15" OR lower(PreAuthType)="16" OR lower(PreAuthType)="17")
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Find the certificate (serial and issuer are in the event) and when it was issued on the CA (4886/4887).
2. If the account is privileged and does not use smart cards, revoke the certificate and check the template it came from.

## Known false positives

- Smart card and Windows Hello for Business logons. Exclude the accounts and devices that use them.
