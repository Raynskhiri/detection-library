# DL-0055 · Service principal name added to a user account (targeted Kerberoasting)

**ATT&CK:** [T1558.003](https://attack.mitre.org/techniques/T1558/003/), [T1098](https://attack.mitre.org/techniques/T1098/) · **Tactic:** credential-access · **Severity:** medium · **Data:** `windows_event`

Event 5136 writing servicePrincipalName on a user object. With write rights on a user, an attacker can add any SPN, request a service ticket for it and crack the user's password offline, then remove the SPN again.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_object_class = json_extract_scalar(action_evtlog_data_fields, "$.ObjectClass"), evt_attribute_name = json_extract_scalar(action_evtlog_data_fields, "$.AttributeLDAPDisplayName")
| filter action_evtlog_event_id = 5136 and evt_attribute_name = "serviceprincipalname" and evt_object_class = "user"
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=5136 AND lower(AttributeLDAPDisplayName)="serviceprincipalname" AND lower(ObjectClass)="user"
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Check for an RC4 service ticket for that account right after (DL-0047) and whether the SPN was removed again.
2. Reset the account's password to a long random value.

## Known false positives

- Admins creating a service account for a new application.
