# DL-0048 · TGT issued without Kerberos pre-authentication (AS-REP roasting)

**ATT&CK:** [T1558.004](https://attack.mitre.org/techniques/T1558/004/) · **Tactic:** credential-access · **Severity:** high · **Data:** `windows_event`

Event 4768 with pre-authentication type 0 means the account has "Do not require Kerberos preauthentication" set, and anyone can request a TGT for it and crack the reply offline.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_preauth_type = json_extract_scalar(action_evtlog_data_fields, "$.PreAuthType")
| filter action_evtlog_event_id = 4768 and evt_preauth_type = "0"
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=4768 AND lower(PreAuthType)="0"
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Turn pre-authentication back on for the account and reset its password.
2. Check who else has DONT_REQ_PREAUTH (Get-DomainUser -PreauthNotRequired) and who can set it.

## Known false positives

- Accounts that really need no pre-auth (rare, some old Unix integrations). List them and review why.
