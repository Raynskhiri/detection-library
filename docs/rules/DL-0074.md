# DL-0074 · Admin or SSL VPN login with an account name used in FortiGate intrusions

**ATT&CK:** [T1078](https://attack.mitre.org/techniques/T1078/), [T1133](https://attack.mitre.org/techniques/T1133/) · **Tactic:** initial-access · **Severity:** medium · **Data:** `fortigate`

A successful admin or SSL VPN login by an account named like the backdoors reported in the 2026 FortiGate campaigns (support, ssl-admin, backupadmin, itadmin, secadmin, svcadmin, remoteadmin, adccount, audit, deploy). These are created to blend in, so the name alone is a lead, not proof. FortiGate event log only.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = fortinet_fortigate_raw
| filter _raw_log != null
| alter fg_logid = arrayindex(regextract(_raw_log, "\\blogid=\"?([^\"\\s]*)"), 0), fg_subtype = arrayindex(regextract(_raw_log, "\\bsubtype=\"?([^\"\\s]*)"), 0), fg_action = arrayindex(regextract(_raw_log, "\\baction=\"?([^\"\\s]*)"), 0), fg_status = arrayindex(regextract(_raw_log, "\\bstatus=\"?([^\"\\s]*)"), 0), fg_user = arrayindex(regextract(_raw_log, "\\buser=\"?([^\"\\s]*)"), 0), fg_srcip = arrayindex(regextract(_raw_log, "\\bsrcip=\"?([^\"\\s]*)"), 0), fg_ui = arrayindex(regextract(_raw_log, "\\bui=\"?([^\"\\s]*)"), 0), fg_devname = arrayindex(regextract(_raw_log, "\\bdevname=\"?([^\"\\s]*)"), 0), fg_logdesc = arrayindex(regextract(_raw_log, "\\blogdesc=\"([^\"]*)\""), 0), fg_msg = arrayindex(regextract(_raw_log, "\\bmsg=\"([^\"]*)\""), 0)
| filter ((fg_subtype in ("system", "vpn") and fg_action in ("login", "tunnel-up", "ssl-login")) and fg_user in ("support", "ssl-admin", "backupadmin", "backup", "itadmin", "secadmin", "svcadmin", "remoteadmin", "adccount", "audit", "deploy", "security", "helpdesk")) and not ((fg_status != null and fg_status in ("failed", "failure")))
| fields _time, fg_devname, fg_logid, fg_user, fg_srcip, fg_ui, fg_logdesc, fg_msg
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`fortigate`
| where (((lower(subtype)="system" OR lower(subtype)="vpn") AND (lower(action)="login" OR lower(action)="tunnel-up" OR lower(action)="ssl-login")) AND (lower(user)="support" OR lower(user)="ssl-admin" OR lower(user)="backupadmin" OR lower(user)="backup" OR lower(user)="itadmin" OR lower(user)="secadmin" OR lower(user)="svcadmin" OR lower(user)="remoteadmin" OR lower(user)="adccount" OR lower(user)="audit" OR lower(user)="deploy" OR lower(user)="security" OR lower(user)="helpdesk")) AND NOT ((isnotnull(status) AND (lower(status)="failed" OR lower(status)="failure")))
| table _time devname logid user srcip ui logdesc msg
| sort - _time
```

## Triage

1. Check when the account was created (DL-0069). If nobody on your team created it, disable it and start incident response.
2. For a VPN login, list everything the tunnel IP touched in the traffic log for the session.

## Known false positives

- A real account with one of these names. Rename it to something personal and tie it to a person, so this rule stays useful.
