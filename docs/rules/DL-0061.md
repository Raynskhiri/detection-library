# DL-0061 · Certificate issued with a subject alternative name supplied in the request

**ATT&CK:** [T1649](https://attack.mitre.org/techniques/T1649/) · **Tactic:** credential-access · **Severity:** high · **Data:** `windows_event`

CA event 4886 or 4887 where the request attributes carry a SAN (san:upn=...). If the template lets the requester choose the subject (ESC1), or the CA accepts SAN attributes (ESC6), any user can get a certificate for an administrator and log on with it.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_cert_attributes = json_extract_scalar(action_evtlog_data_fields, "$.Attributes")
| filter action_evtlog_event_id in (4886, 4887) and evt_cert_attributes ~= "(?i)san:.*(upn|dns)="
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where (EventCode=4886 OR EventCode=4887) AND match(Attributes, "(?i)san:.*(upn|dns)=")
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Compare the requester with the identity in the SAN. A normal user asking for an admin's UPN is an attack.
2. Revoke the certificate and remove ENROLLEE_SUPPLIES_SUBJECT or the EDITF_ATTRIBUTESUBJECTALTNAME2 flag.

## Known false positives

- Web server or device templates where the requester supplies DNS names by design. Exclude those templates.
