# DL-0026 · Connection to common Tor ports from a non-Tor process

**ATT&CK:** [T1090.003](https://attack.mitre.org/techniques/T1090/003/) · **Tactic:** command-and-control · **Severity:** medium · **Data:** `network_connection`

Outbound connections to 9001, 9030, 9050, 9051 or 9150, the default Tor relay, directory and SOCKS ports, from something that is not the Tor client. Malware uses Tor for C2 and ransomware groups use it for their negotiation and leak sites.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.NETWORK and action_remote_ip != null
| filter action_remote_port in (9001, 9030, 9050, 9051, 9150) and not ((actor_process_image_name != null and actor_process_image_name in ("tor.exe", "firefox.exe")))
| fields _time, agent_hostname, actor_process_image_name, actor_process_command_line, action_remote_ip, action_remote_port
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`sysmon` EventCode=3
| eval process_name=lower(mvindex(split(Image,"\\"),-1))
| where (DestinationPort=9001 OR DestinationPort=9030 OR DestinationPort=9050 OR DestinationPort=9051 OR DestinationPort=9150) AND NOT ((isnotnull(process_name) AND (lower(process_name)="tor.exe" OR lower(process_name)="firefox.exe")))
| table _time host Image DestinationIp DestinationPort
| sort - _time
```

## Triage

1. Check whether the destination IP is a known Tor relay.
2. Identify the process and how it got there.

## Known false positives

- Unrelated services that happen to use these ports. Check the destination.
