# DL-0071 · FortiGate firewall policy set to accept any source to any destination

**ATT&CK:** [T1562.004](https://attack.mitre.org/techniques/T1562/004/), [T1133](https://attack.mitre.org/techniques/T1133/) · **Tactic:** persistence · **Severity:** high · **Data:** `fortigate`

A firewall policy was added or edited so that both the source and destination address are "all" and the action is accept. In one 2026 FortiGate intrusion the attacker added four such policies to open every zone to every other zone. Real admins rarely write an all-to-all accept rule, so it is a cheap, strong signal. FortiGate event log only.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = fortinet_fortigate_raw
| filter _raw_log != null
| alter fg_logid = arrayindex(regextract(_raw_log, "\\blogid=\"?([^\"\\s]*)"), 0), fg_action = arrayindex(regextract(_raw_log, "\\baction=\"?([^\"\\s]*)"), 0), fg_user = arrayindex(regextract(_raw_log, "\\buser=\"?([^\"\\s]*)"), 0), fg_srcip = arrayindex(regextract(_raw_log, "\\bsrcip=\"?([^\"\\s]*)"), 0), fg_ui = arrayindex(regextract(_raw_log, "\\bui=\"?([^\"\\s]*)"), 0), fg_cfgpath = arrayindex(regextract(_raw_log, "\\bcfgpath=\"?([^\"\\s]*)"), 0), fg_devname = arrayindex(regextract(_raw_log, "\\bdevname=\"?([^\"\\s]*)"), 0), fg_logdesc = arrayindex(regextract(_raw_log, "\\blogdesc=\"([^\"]*)\""), 0), fg_msg = arrayindex(regextract(_raw_log, "\\bmsg=\"([^\"]*)\""), 0), fg_cfgattr = arrayindex(regextract(_raw_log, "\\bcfgattr=\"([^\"]*)\""), 0)
| filter (fg_cfgpath = "firewall.policy" and fg_action in ("add", "edit")) and (fg_cfgattr ~= "(?i)srcaddr\\[([^\\]]*->)?all\\]" and fg_cfgattr ~= "(?i)dstaddr\\[([^\\]]*->)?all\\]")
| fields _time, fg_devname, fg_logid, fg_user, fg_srcip, fg_ui, fg_logdesc, fg_msg
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`fortigate`
| where (lower(cfgpath)="firewall.policy" AND (lower(action)="add" OR lower(action)="edit")) AND (match(cfgattr, "(?i)srcaddr\\[([^\\]]*->)?all\\]") AND match(cfgattr, "(?i)dstaddr\\[([^\\]]*->)?all\\]"))
| table _time devname logid user srcip ui logdesc msg
| sort - _time
```

## Triage

1. Read cfgobj (the policy ID) and cfgattr, then check which interfaces the policy joins. WAN to LAN is an emergency.
2. Look at who made the change and how they logged in (DL-0068). Then search the traffic log for sessions that used the new policy ID.

## Known false positives

- Temporary troubleshooting rules. They should have a ticket and be deleted the same day.
