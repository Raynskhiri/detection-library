# DL-0067 · Web server or PHP-FPM worker crashed with a segmentation fault

**ATT&CK:** [T1190](https://attack.mitre.org/techniques/T1190/) · **Tactic:** initial-access · **Severity:** medium · **Data:** `web_server_error`

Apache AH00051 / AH00052 "exit signal Segmentation fault" or PHP-FPM "exited on signal 11 (SIGSEGV)". Memory corruption exploits such as PHP2Shell often crash a few workers before one attempt works, so crashes on an internet-facing PHP server are worth a look.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = apache_httpd_raw
| filter _raw_log != null
| filter _raw_log ~= "(?i)ah0005[12].*segmentation fault" or _raw_log contains "exited on signal 11"
| fields _time, _raw_log
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`apache_error`
| where match(_raw, "(?i)ah0005[12].*segmentation fault") OR match(_raw, "(?i)exited\\ on\\ signal\\ 11")
| table _time host _raw
| sort - _time
```

## Triage

1. Look at the requests just before the crash (access log, same second). Large multipart POSTs from one source point to exploitation.
2. Check for PHP memory errors from the same client (DL-0066) and for processes under the worker (DL-0063).

## Known false positives

- Buggy PHP extensions or modules that crash under load. Those crash at the same code path every time; check with the vendor.
