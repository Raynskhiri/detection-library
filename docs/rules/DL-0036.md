# DL-0036 · winrs runs a command on another host

**ATT&CK:** [T1021.006](https://attack.mitre.org/techniques/T1021/006/) · **Tactic:** lateral-movement · **Severity:** medium · **Data:** `process_creation`

winrs -r:host runs a command on a remote machine over WinRM. It is the source side of DL-0024 and shows up on the attacker's foothold, often right after a Kerberos ticket was injected for the target.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.PROCESS and event_sub_type = ENUM.PROCESS_START
| filter action_process_image_name = "winrs.exe" and action_process_image_command_line ~= "(?i)(-|/)r(emote)?:"
| fields _time, agent_hostname, actor_effective_username, actor_process_image_name, action_process_image_name, action_process_image_command_line
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`sysmon` EventCode=1
| eval process_name=lower(mvindex(split(Image,"\\"),-1)), parent_name=lower(mvindex(split(ParentImage,"\\"),-1))
| where lower(process_name)="winrs.exe" AND match(CommandLine, "(?i)(-|/)r(emote)?:")
| table _time host User ParentImage Image CommandLine
| sort - _time
```

## Triage

1. Check the target host for wsmprovhost.exe children (DL-0024) and the type 3 logon in its Security log.
2. If the same session injected a ticket just before (DL-0031), treat the account on the target as compromised.

## Known false positives

- Admins who use winrs for remote maintenance. Baseline who and from where.
