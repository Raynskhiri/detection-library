# DL-0060 · Logon with new credentials (logon type 9, overpass-the-hash)

**ATT&CK:** [T1550.002](https://attack.mitre.org/techniques/T1550/002/), [T1134.002](https://attack.mitre.org/techniques/T1134/002/) · **Tactic:** lateral-movement · **Severity:** medium · **Data:** `windows_event`

Event 4624 with logon type 9 and the seclogo logon process. It is what runas /netonly creates, and also what mimikatz sekurlsa::pth and Rubeus createnetonly create when they start a process that uses a stolen hash or ticket for network access.

## Cortex XDR (XQL)

```sql
config case_sensitive = false
| dataset = xdr_data
| filter event_type = ENUM.EVENT_LOG
| alter evt_subject_user = json_extract_scalar(action_evtlog_data_fields, "$.SubjectUserName"), evt_target_user = json_extract_scalar(action_evtlog_data_fields, "$.TargetUserName"), evt_logon_type = json_extract_scalar(action_evtlog_data_fields, "$.LogonType"), evt_logon_process = json_extract_scalar(action_evtlog_data_fields, "$.LogonProcessName")
| filter action_evtlog_event_id = 4624 and evt_logon_type = "9" and evt_logon_process contains "seclogo"
| fields _time, agent_hostname, action_evtlog_event_id, evt_subject_user, evt_target_user, action_evtlog_message
| sort desc _time
| limit 1000
```

## Splunk (SPL, Sysmon)

```
`wineventlog`
| where EventCode=4624 AND lower(LogonType)="9" AND match(LogonProcessName, "(?i)seclogo")
| table _time host EventCode SubjectUserName TargetUserName Message
| sort - _time
```

## Triage

1. Find the process that started the logon session and what it connected to.
2. Any type 9 logon on a workstation of a normal user is worth asking about.

## Known false positives

- Admins using runas /netonly to manage other domains. Baseline the hosts and accounts.
